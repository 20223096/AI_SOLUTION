# 일정 최적화 진단

검증일은 2026-10-26, 15분 슬롯, 분석 구간 07:00~18:00입니다. 알려진 작업 540분을 순차 수행하므로 가능한 시작은 07:00~09:00의 9개입니다. 각 작업 시작을 같은 오프셋만큼 옮기기 때문에 작업시간·선행관계·공용 작업구역 제약은 보존됩니다. 작업별 독립 이동은 아직 탐색하지 않으므로 탐색공간은 의도적으로 제한되어 있지만, 시작시간이 고정된 것은 아닙니다.

## CASE A 후보 진단

생성 9, 실행 가능 9, 불가능 0, Pareto 1개입니다.

| 후보 | 시작 | 주민 영향비용 | 변경량(작업별 합계, 분) | Pareto/지배 사유 |
|---|---:|---:|---:|---|
| offset-0 | 07:00 | 1472.53 | 0 | Pareto |
| offset-15 | 07:15 | 1472.58 | 60 | offset-0이 지배 |
| offset-30 | 07:30 | 1472.58 | 120 | offset-0이 지배 |
| offset-45 | 07:45 | 1472.58 | 180 | offset-0이 지배 |
| offset-60 | 08:00 | 1472.58 | 240 | offset-0이 지배 |
| offset-75 | 08:15 | 1472.58 | 300 | offset-0이 지배 |
| offset-90 | 08:30 | 1472.58 | 360 | offset-0이 지배 |

2차 계산식 보정으로 기존 문서의 968.88은 1472.53으로 바뀌었습니다. 이제 수음점별 영향점수를 합산하며, 민감도 성분은 실제 노출과 곱해집니다. 원 일정만 남는 이유는 기본 시나리오에 기존 이벤트가 없고 대부분 슬롯의 명시된 가상 배경이 동일하여 시간 이동의 이득이 거의 없는 반면, 이동량은 반드시 증가하기 때문입니다. offset-0은 주민비용도 0.05 낮고 변경량도 낮아 나머지 전부를 지배합니다.

기존 `existing_events.json`은 1차 구현에서 계산에 연결되지 않았습니다. 2차에서는 수음점별 기존 이벤트 Lp를 에너지 합산하고 `existing_event_ids`, 출처, 중첩 슬롯을 응답합니다. CASE A에는 입력 이벤트가 없으므로 반영값은 없습니다. 수음점별 배경과 민감도는 각 receptor-slot의 Impact에 반영됩니다. 과거 구현처럼 대학 시험 민감도를 모든 시나리오에 강제하지 않습니다.

## 실험 시나리오

### A — 기본 가정

CASE A 그대로입니다. 9/9개 실행 가능, Pareto는 offset-0 하나입니다. Before/After 모두 연속 고소음 180분, Quiet Window 480분, 최대 Impact 41.60, 누적 Impact 1472.53, 변경 0분입니다.

### B — 소음 집중

07:00~09:00 가정 공사 Lp 82 dBA와 09:00~09:30 가정 수거 Lp 75 dBA를 에너지 합산합니다. 모두 `assumed`입니다. 생성/실행 가능 9개, Pareto 4개(offset-0/90/105/120)입니다.

| 후보 | 주민비용 | 변경량 | 기존소음 중첩 receptor-slot | 기본 Impact | 중첩부담 |
|---|---:|---:|---:|---:|---:|
| offset-0 | 2665.66 | 0 | 26 | 1885.66 | 780 |
| offset-90 | 2655.36 | 360 | 8 | 2415.36 | 240 |
| offset-105 | 2627.26 | 420 | 5 | 2477.26 | 150 |
| offset-120 | 2599.16 | 480 | 2 | 2539.16 | 60 |

주민 보호 선택은 offset-120(09:00 시작)입니다. 중첩 회피는 성공하지만 순수 Impact 합계와 연속 고소음시간은 오히려 증가합니다. 이는 포화·절단되는 점수에서 소음을 한 시간대에 겹치면 합계가 작아지는 현상 때문입니다. 이를 숨기지 않고, B에서는 가정된 정책계수 `기존소음 중첩 receptor-slot당 30`을 별도 목적항으로 사용했습니다. 이 계수도 검증자료가 아닌 `assumed`이며 실제 정책 결정 전에 보정해야 합니다.

### C — 대학 시험기간

08:00~10:00 시험시간 +0.5는 `assumed`입니다. 민감도 비활성 시 Pareto는 offset-0 하나(1441.53)입니다. 활성 시 9개 모두 변경비용 증가와 주민비용 감소의 trade-off여서 Pareto에 남습니다. 공사 편의/균형은 offset-0(1501.89), 주민 보호는 offset-120(1481.42, 변경 480분)입니다. 물리 dB는 두 실험에서 동일하고 영향점수와 추천 우선순위만 바뀝니다.

### D — 제약 강화

12:00~14:00 금지시간, 같은 날 복구, 모든 공정시간 필수 조건입니다. 9개 모두 불가능하고 추천은 0개입니다. 모든 후보가 금지시간과 충돌하며 포장 복구 소요시간도 누락되어 같은 날 복구를 검증할 수 없습니다.

## API 진단

기존 `POST /api/schedules/optimize` 응답을 유지하고 `diagnostics`를 추가했습니다. 별도 `GET /api/schedules/optimize/{scenario_id}/diagnostics?analysis_date=2026-10-26&sensitivity_enabled=true`로 생성/실행 가능/Pareto 수, 전 후보 지표, 지배 후보와 사유를 조회할 수 있습니다.
