# 공식 설계자료 데이터 통합

## 1. 통합 목적과 경계

나라장터 공고 `R26BK01661205`의 설계정보를 `official-construction-design-v1`로 정규화했다. 원본 검토 근거는 `CONSTRUCTION_DOCUMENT_AUDIT.md`와 원본 6개이며, 불명확한 수량·위치·시간은 원본과 재대조했다. 이 버전은 **설계 메타데이터와 데이터 결손을 제공**하며 새로운 소음 예측 시나리오가 아니다.

- 데이터: `data/processed/official_construction_design_v1.json`
- API: `GET /api/public-data/construction-design`
- 기존 API 확장: `GET /api/public-data/catalog`의 `official_construction_design`
- 기존 시나리오, 소음 예측식, 최적화 목적함수: 변경 없음
- 음향 예측 및 거리 계산 상태: `deferred`

provenance 값은 `official_design_document`, `official_equipment_reference`, `derived`, `assumed`, `unknown`만 사용한다. 별도 표기가 없는 설계 필드는 데이터셋의 `official_design_document`를 상속하고, `null`은 `unknown`이다. 공식 장비 검사자료의 존재는 `official_equipment_reference`일 뿐 현장 장비 확정을 의미하지 않는다.

119건의 `롤러/다짐기계` 모델명은 롤러 계열이고 ‘램머’ 레코드는 없다. 램머는 충격 다짐 장비이며 롤러와 운전 방식·접촉 조건이 다르므로 같은 대표 Lw를 적용하지 않는다. 덤프트럭·펌프도 굴착기 Lw로 대체하지 않는다.

공식 검사자료에는 개별 모델 Lw가 있지만 이 공사의 장비대장과 모델 조인이 불가능하다. 따라서 현재 사용할 수 있는 것은 장비군별 **불확실성 범위 탐색의 후보 자료**뿐이고, 그 결과도 `assumed` 또는 `official_equipment_reference` 기반 민감도 분석으로 표시해야 한다.

## 5. 공식 기간과 시뮬레이션 일정 분리

| 공식 기간 산정 | 일수 | 용도 |
|---|---:|---|
| 총 계획 공사기간 | 140 | 사업계획 메타데이터 |
| 준비 | 7 | 기간 산정 |
| 비작업 | 59 | 기후·공휴일 등을 반영한 산정 |
| 작업 | 67 | 주요 공종 작업일 합계 |
| 정리 | 7 | 기간 산정 |
| 터파기·되메우기 | 31 | 작업일 산정 근거 |
| 관 부설 | 31 | 작업일 산정 근거 |
| 포장 | 5 | 작업일 산정 근거 |

31+31+5=67이지만 일별 확정 공정, 공종의 완전 순차성, 두 구간별 배분 또는 장비별 가동시간은 아니다. `daily_work_window`와 `calendar_schedule`은 `unknown`이다. 이 값을 착공일에 연결해 67일 달력을 생성하지 않는다.

기존 07:00~18:00 창과 540분 시퀀스는 별도 `assumed_demo_schedule_reference`로 유지된다. `case-a`를 포함한 기존 단일일 시나리오 데이터는 바꾸지 않았다.

## 6. API의 계산 가능/보류 표시

설계 데이터의 `calculation_readiness`는 다음을 명시한다.

- 현재 가능: 설계수량 조회, 두 구간 연장 합계 검증, 장비 데이터 결손 분석.
- 현재 보류: 음향 예측, 수음점 거리 계산.
- 보류 이유: 실제 선형/음원점, 구간별 수음점, 실제 장비 모델, 운전시간·가동률, 동시가동 계획, 미매칭 장비 소음자료, 현장 측정자료 없음.

`/api/public-data/catalog`에는 기존 키를 유지한 채 `official_construction_design`만 추가했다. 정책에는 `official_design_is_acoustic_scenario=false`, `nominal_address_is_distance_source=false`를 추가했다. 새로운 시나리오 ID를 만들지 않았으므로 `/api/noise/predict`가 이 자료를 실제 소음 시나리오로 수락하지 않는다.

## 7. 추가 입력과 공개 확보 가능성

| 자료 | 필요성 | 가능한 확보 경로 | 현재 상태 |
|---|---|---|---|
| 실제 공사구간 선형 | 거리·차폐·구간별 음원 배치에 필수 | 설계 평면도/종단면도, 측량 성과, 도로굴착 도면을 발주부서 또는 정보공개로 요청 | `unknown` |
| 구간별 수음점 | 수음점별 예측에 필수 | 현장조사로 좌표·높이·용도를 정하거나 공식 시설 좌표를 후보로 검토 | `unknown` |
| 실제 장비 모델 | 검사자료 정확 매칭에 필수 | 착공계 부속 장비투입계획, 장비대장, 대여계약 | `unknown` |
| 운전시간·가동률 | 등가노출 계산에 필수 | 작업계획서, 일일 작업일보, 장비 운전기록 | `unknown` |
| 동시 운영 장비 | 에너지 합성에 필수 | 예정공정표, 일일 작업계획·작업일보 | `unknown` |
| 덤프트럭·램머·펌프 소음 | 누락 음원 계산에 필수 | 동일 규격 시험성적서·인증자료 또는 현장 근접 측정 | 보유 공개 CSV에는 없음 |
| 현장 측정자료 | 모델 보정·검증에 필수 | 소음·진동 신고서 부속자료, 착공 전 배경/공사 중 측정, 정보공개 요청 | `unknown` |

나라장터의 현재 6개 첨부만으로는 위 자료가 확보되지 않았다. 서울시 정보소통광장은 공개·부분공개·비공개 첨부가 혼재하므로 검색 또는 정보공개청구 경로는 존재하지만, 이 특정 공사의 자료가 공개된다고 보장할 수 없다. 계약·착공 뒤 One-PMIS에 등록되는 공정계획은 접근 권한과 공개 여부를 별도로 확인해야 한다.

자료가 없을 때 가능한 것은 범위 기반 불확실성 시뮬레이션뿐이다. 장비군 Lw 분포, 가동률 범위, 임시 수음점/거리 범위를 명시해 Monte Carlo 또는 경계값 분석을 할 수 있으나 모든 입력을 `assumed`로 반환하고 실제값·확정 예측과 분리해야 한다. 램머를 롤러로 대체하거나 주소 대표점을 실제 선형으로 간주하는 방식은 허용하지 않는다.

## 8. 자동화 검증

추가 테스트는 다음을 검증한다.

- 두 구간의 분리와 geometry/대표점 `null`.
- 328+155=483m.
- 설계수량·단위·원본 셀 근거 보존.
- 실제 모델과 운전시간이 `null`.
- 램머/롤러 오매칭과 덤프트럭·펌프 대체 차단.
- 67일 산정과 일일 작업시간 분리.
- 기존 `case-a`의 07:00~18:00, 540분 가정 회귀.
- GIS가 없을 때 거리·음향 계산 보류.
- 카탈로그 하위 호환과 전용 엔드포인트.

## 9. 다음 M1 물리 모델 범위

M1은 공식 설계수량을 곧바로 dB로 변환하는 단계가 아니다. 다음 입력 계약과 계산 경계를 먼저 구현하는 것이 적절하다.

1. 선/점 음원 geometry와 좌표계, 수음점 좌표·높이의 검증 스키마.
2. 실제 장비 모델과 공식 Lw 레코드의 정확 조인 및 미매칭 차단.
3. 장비별 가동률·운전구간·동시가동을 시간 슬롯별 에너지로 변환하는 입력 모델.
4. 거리 발산, 지면·차폐·방음시설 보정의 독립 항과 근거/불확실성 반환.
5. 덤프트럭 이동음원, 고정 펌프, 충격성 램머를 서로 다른 음원 형태로 처리.
6. 현장 측정값과 예측값의 잔차 검증 및 보정 전/후 버전 분리.
7. 확정 입력과 불확실성 표본을 분리한 결과 API.

실제 장비와 현장 측정이 없으면 M1은 검증된 주민 피해 감소를 주장할 수 없고, 조건부 예측과 데이터 확보 우선순위만 제공해야 한다.
