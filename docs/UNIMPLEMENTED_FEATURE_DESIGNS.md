# 미구현 PRD 기능 계약 설계안

정책 승인 전 설계안이며 현재 OpenAPI에 존재하지 않는다.

## F9 주민 안내문 생성·승인

- 입력: 승인 대상 notice ID, 확정 candidate ID, 공개 가능한 기간·작업·주의사항, 근거 provenance, 작성 언어.
- 출력: `draft_id`, `status=draft|reviewed|approved|rejected`, 초안 문구, 사용 근거, 누락/경고, 승인자와 시각.
- 정책: 생성 결과는 항상 `draft`; 권한 있는 사용자의 별도 승인 전 배포·확정 표현 금지. 행정기관 로고·직인·공문번호 자동 생성 금지.
- 영향: 새 저장소, 감사로그, `POST /drafts`, `POST /drafts/{id}/approve` 계열이 필요하다.

## F10 주민 전용 조회

- 입력: 승인·공개된 공사 식별자 또는 제한된 공개 토큰.
- 출력: 정밀도를 낮춘 위치, 승인된 작업시간, 예상 불편 구간, 승인된 안내문, 문의처, 모델/가정 고지.
- 정책: 내부 장비·신고 원문·개인정보·미승인 위치 및 후보는 제외한다. 공개기간과 철회/캐시 정책이 필요하다.
- 영향: 내부 모델의 별도 public projection과 접근·rate-limit 검토가 필요하다.

## F11 자연어 조건 수정

- 1단계 입력/출력: 자연어와 대상 notice 버전 → 구조화된 `proposed_diff`, 신뢰도, 원문 근거, 충돌·누락 경고. 계산에는 적용하지 않는다.
- 2단계 입력/출력: 사용자가 확인한 diff와 대상 버전 → 승인된 제약 버전 및 재검증 결과.
- 정책: 사용자 승인 전 optimizer에 전달 금지, 허용 필드 whitelist, 낙관적 버전 잠금과 감사로그 필요.
- 영향: LLM 비결정성을 격리하는 새 API와 저장 모델이 필요하다.

## F12 법 기준 참고 표시

- 입력: 관할, 공종, 시간대, 측정지점·방법 등 기준 선택에 필요한 조건.
- 출력: 버전된 기준표 항목, 공식 출처·시행일·적용조건, 충족되지 않은 입력, PoC 분석결과와의 비비교 경고.
- 정책: 현장 측정과 적용조건이 없으면 `not_evaluable`; 자동 `violation`/`compliant` 결론 금지.
- 영향: 법무 검토를 거친 기준 데이터셋과 변경 이력 API가 필요하다.
